# 부스 50개 · 학생 3,000명 · 3분 혼합 테스트

실행일: 2026-09-29, 대상: `http://43.202.5.26:8000`.

**실행은 완료됐지만 기준 미달이다. Windows 부하 발생기의 소켓 포트 부족도 발생했으므로,
94.16% 실패를 백엔드 자체의 실패율로 해석할 수 없다.**

## 실행 방식

- 임시 부스 50개, 서로 다른 테스트 학생 3,000명을 관리자 API로 생성했다.
- 학생 한 명당 k6 VU 하나를 배정했다. 3,000명 모두 참여했다.
- 첫 조회는 0~15초에 분산하고, 이후 행동 사이에 3~8초를 기다렸다.
- 행동 선택 확률: 본인 페이지 50%, 무작위 부스 조회 20%, 방문 인증 후 본인 페이지 확인 30%.
- 180초 동안 새 행동을 실행하고 진행 중인 행동의 종료를 기다렸다. 측정 집계에는 약 23초의 종료 대기가 추가됐다.
- 준비/정리는 180초 부하 구간과 별도다. 카드 이미지와 브라우저 렌더링, 공유 페이지, 역량 점수 검증은 제외했다.

## 결과

| 항목 | 실측 |
|---|---:|
| 참여한 학생 | 3,000명 |
| 준비한 테스트 부스 | 50개 |
| HTTP 요청 시도 | 57,439건 |
| HTTP 성공 | 3,356건 |
| HTTP 실패 | 54,083건 (94.16%) |
| 행동 시도 완료 | 56,205회 |
| 데이터까지 검증된 행동 | 2,122회 (3.78%) |
| 성공 응답으로 확인한 신규 인증 | 1,216건 |
| 성공 응답으로 확인한 중복 인증 | 18건 |
| 조회·부스 조회·방문 인증 p95 | 각각 약 8초 |

요청 제한은 8초다. p95가 제한에 도달했으므로 서버가 실제로 처리 완료하는 데 필요한
시간을 나타내는 수치는 아니다. 실패율에는 HTTP 오류뿐 아니라 연결 실패와 시간 초과가 포함된다.
타임아웃된 POST가 서버에서 처리됐을 가능성도 있어 신규 인증 수는 DB의 실제 삽입 수와 다를 수 있다.

## 실행 중 관찰

1. 21:08:13경 k6를 시작했고, 21:08:23경부터 다수의 8초 요청 시간 초과가 발생했다.
2. 21:09:51경 해당 서버 연결에서 TIME_WAIT 14,185개, SYN_SENT 825개를 관찰했다.
3. 이후 Windows `connectex: Only one usage of each socket address ...` 오류가 발생했다.
   이 요청들은 서버 응답을 기다린 것이 아니라 클라이언트의 연결 생성 단계에서 실패했다.
4. 관찰 시 k6 메모리는 약 1GB였다. CPU/메모리의 전체 구간 모니터링을 수행한 것은 아니다.
5. 부하 종료 후 `/healthz`는 HTTP 200, 약 0.67초에 응답했다.

이 결과로 현재 로컬 실행 환경에서 해당 부하를 정상 처리하지 못한다는 점은 확인했다.
백엔드 수용량을 분리해서 판단하려면 소켓 여유가 있는 부하 발생 환경에서 재측정하고,
같은 시각의 서버 CPU·DB 연결 대기·쿼리 시간을 함께 관찰해야 한다.
이번 실행에서 서버 내부 병목 원인이나 정확한 최대 동시 수용 인원은 확정하지 않았다.

## 재실행

프로젝트 루트에서 다음 명령을 실행한다. 관리자 정보는 입력창에서 입력하며 저장하지 않는다.

```powershell
.\backend\tests\load\run.ps1 -PromptAdmin -Profile mixed
```

같은 PC·조건으로 바로 반복하면 같은 소켓 부족이 재발할 수 있다.
후속 실행의 k6 경고는 결과 폴더의 `mixed.log`에 저장하도록 변경했다.

원본 결과: `results/mixed-d2cc6efd-88ad-4efa-a5c3-0e1624cb8f30/mixed.json`.
실행 범위: 같은 폴더의 `scope.json`.
학생 삭제 기록: `students-owned.json`, 부스 삭제 기록: `booth-*-owned.json`.

**정리 완료:** 생성한 학생 3,000명과 부스 50개를 삭제했다. 소유 기록 51개가 모두 빈 배열이며,
학생 토큰 파일도 제거된 것을 확인했다. 기존 학생과 기존 부스는 삭제하지 않았다.

러너 관련 단위 테스트 7개 통과, Ruff·PowerShell 구문 검사 통과.
