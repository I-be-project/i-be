# 개인 페이지 원격 k6 실행 결과 — 2026-09-29

대상: `http://43.202.5.26:8000`. 로컬 Windows에서 실행했다.
관리자 API로 `kind=test` 학생을 준비하고 서버가 발급한 학생 토큰을 사용했다.
학생 JSON 작성, 직접 DB 접속, 로컬 JWT 키 설정은 필요하지 않다.

**본인 조회 500명/10초는 통과했지만, 부스 인증 500명/10초는 응답 시간 기준을 넘었다.**
오류나 잘못된 방문 기록은 검출되지 않았으며 부하 이후 조회 응답 속도는 회복됐다.

부스 인증 기본 확인에서는 학생 11명으로 신규 인증 11건, 중복 인증 49건을 검사했다.
기준은 API p95 < 800ms, HTTP 실패율 < 1%, 응답 데이터 검증 성공률 100%,
계획한 흐름 수 완료, 누락된 실행 0건이다. 방문 전체 흐름 기준은 p95 < 4800ms다.

|---|---|---|
| 본인 조회 | 2.39초 | 800ms 미만 |
| 부스 조회 | 1.29초 | 800ms 미만 |
| 신규 인증 | 1.32초 | 800ms 미만 |

신규 인증 500건·중복 인증 500건 모두 상태/시각 검증을 통과했다.
집중 및 회복 구간의 총 3,900요청에서 HTTP 실패는 0건, 실행 누락도 0건이었다.
전체 흐름의 8.44초에는 검증을 위한 중복 인증과 반복 조회까지 6개 요청이 포함되므로
이를 실제 UI에서 버튼 한 번 누른 응답 시간으로 해석하면 안 된다.
10초는 500명이 흐름을 **시작하는** 기간이며 모든 요청이 10초 안에 끝났다는 뜻은 아니다.

시간 기준 미달로 더 높은 부하는 실행하지 않았다. 서버 CPU, DB 연결 대기, 쿼리 지연을
관찰하면서 방문 부하를 재측정해야 원인을 구분할 수 있다. 클라이언트 결과만으로
특정 쿼리나 DB 연결 풀을 원인으로 확정할 수는 없다.

생성한 테스트 학생 총 1,012명과 임시 부스 2개는 관리자 삭제 API로 정리했다.
모든 소유 ID 기록이 빈 배열이고 임시 학생 토큰 파일이 제거된 것을 확인했다.
기존 학생이나 부스는 삭제하지 않았다. 비밀번호는 결과 파일에 남기지 않았다.

러너 관련 Python 테스트 24개 통과, Ruff 검사 및 PowerShell 구문 검사도 통과했다.

## 측정 범위

- 본인 페이지: `GET /api/students/me`.
- 방문 흐름: 본인 조회 → 부스 조회 → 방문 인증 → 본인 조회 → 중복 인증 → 본인 조회.
- 공유 페이지 제외. 카드 이미지가 없는 완료 프로필을 사용했다.
- 이미지 생성·다운로드, 카드 URL 서명, 브라우저 렌더링은 측정하지 않았다.
- 배포 서버 응답에 역량 점수가 없어 점수 검증은 제외했다.
- 500명/10초는 초당 50명 진입이다. 500명의 정확한 동시 접속을 검증한 결과가 아니다.
- 5초 집중, 동시 100/300/500명, 장시간 단계 부하는 아직 실행하지 않았다.

## 재실행

프로젝트 루트에서 실행한다. 관리자 아이디는 Enter로 `admin`을 선택하고 비밀번호를 입력한다.
비밀번호는 코드나 결과 파일에 저장하지 않는다.

```powershell
# 본인 조회 + 부스 인증 기본 확인: 각각 2분
.\backend\tests\load\run.ps1 -PromptAdmin

# 500명/10초 + 5분 회복: 본인 조회와 부스 인증 순차 실행
.\backend\tests\load\run.ps1 -PromptAdmin -Profile burst10
```

앞서 계획의 6항목은 검증 목적을 나눈 것이다. 동시 접속을 100/300/500명으로 나누면
실행 프로필은 7개이며, 회복 확인은 집중/동시 프로필에 포함된다.
`-Profile all`은 7프로필 × 2흐름으로 14회 실행하며 기준 미달 시 후속 실행을 멈춘다.
