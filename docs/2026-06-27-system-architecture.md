## 2. 전체 구성도

```
                              HTTPS
   ┌─────────────┐        (443)          ┌──────────────────────────────────────┐
   │  학생/운영자 │ ───────────────────▶ │   AWS Lightsail 인스턴스 (Ubuntu)      │
   │  브라우저    │                       │   ┌────────────────────────────────┐  │
   └─────────────┘                       │   │ Caddy (리버스 프록시·자동 HTTPS)│  │
                                         │   └───────────────┬────────────────┘  │
   ┌─────────────┐                       │   ┌───────────────▼────────────────┐  │
   │ Next.js 16   │  (추후 실연동)        │   │ FastAPI 컨테이너 :8000          │  │
   │ 프론트(별도) │ ───────────────────▶ │   │  - HTTP API (라우터)            │  │
   └─────────────┘                       │   │  - 서비스/리포지토리/어댑터     │  │
                                         │   │  - 인-프로세스 워커(카드 생성)  │  │
                                         │   └───────────────┬────────────────┘  │
                                         └───────────────────┼───────────────────┘
                          ┌──────────────────────────────────┼───────────────────────────┐
                          ▼                                   ▼                           ▼
                 ┌──────────────────┐              ┌──────────────────┐         ┌──────────────────┐
                 │ Supabase Postgres│              │   AWS S3          │         │   OpenRouter     │
                 │  (RDB, IPv6 직결)│              │  photos/ (영구)   │         │  chat + image    │
                 │  schema 4개      │              │  cards/  (영구)   │         │  (Gemini 등)     │
                 └──────────────────┘              └────────┬─────────┘         └──────────────────┘
                                                            │ presigned URL (+선택 CloudFront)
                                                            ▼
                                                     [학생이 이미지 직접 조회 — 앱 미경유]
```

핵심 원칙: **무거운 일은 위임한다.** 연산(LLM·이미지)=OpenRouter, 데이터=Supabase, 파일=S3. Lightsail은 **오케스트레이션(I/O)** 만 담당 → 작은 인스턴스로 충분.

## 4. 컴포넌트 구조

### 4.1 백엔드 레이어드 아키텍처
```
Router      HTTP 진입점 · 입력검증 · 인증가드 · Service 호출
   │
Service     비즈니스 규칙 · 트랜잭션 · 여러 Repo 조합
   │
Repository  DB 쿼리 (Supabase Postgres)
   │
Adapter     외부 시스템 추상화 — AIClient(OpenRouter) · StorageClient(S3) · DBPool · Security(JWT)
   │
Worker      jobs 큐 폴링 → CardService 호출 (자체 로직 없음)
```
- 의존성 방향: `Router → Service → Repository → DB`, Service는 Adapter도 호출.
- **StorageClient = S3 구현** (설계가 어댑터로 추상화해둬서 Supabase Storage→S3 교체가 국소 변경).
- 도메인별 모듈 분할: auth / session / card / persona / operator / admin / reward.

### 4.2 프론트 (현재 단계)
- mock 단계: 흐름 검증을 위해 **Mock API 레이어**(Next route handler)로 실제 백엔드 계약을 흉내.
- 추후 base URL만 교체해 실제 FastAPI로 연결.

## 5. 데이터 저장 전략

### 5.1 무엇을 어디에
| 데이터 | 위치 | 비고 |
|---|---|---|
| 구조화 데이터(계정·세션·답변·페르소나·카드·리워드) | Supabase Postgres | 관계·트랜잭션 |
| 가변 페이로드(답변·원본 AI 응답·메타) | Postgres `jsonb` | 별도 NoSQL 미사용 |
| 얼굴 사진 원본 | **S3 `photos/`** (프라이빗, **영구**) | DB엔 키만 |
| 카드 이미지 | **S3 `cards/`** (프라이빗, 영구) | presigned URL 서빙 |

### 5.2 Postgres 스키마 분리 (권한 격리)
물리 DB 1개 · 논리 schema 4개:
| schema | 책임 | 주 접근자 |
|---|---|---|
| `pii` | 학생 원본(학교/학년/반/번호/이름/동의/사진키) | 본인·관리자 |
| `generated` | 세션·답변·페르소나·카드·공유토큰 | 본인·관리자·운영자(제한) |
| `rewards` | 부스·운영자·리워드 규칙/로그 | 학생(본인)·운영자(자기부스)·관리자 |
| `ops` | jobs 큐·감사로그 | 시스템·관리자 |

> 운영자 토큰은 `pii`에 **구조적으로 접근 불가**. QR 스캔 시 노출은 닉네임+페르소나 타이틀 수준.

### 5.3 식별 키
- 학생 식별 = **(학교, 학년, 반, 번호)** 유니크. 로그인 식별자.

## 6. 학생 흐름과 상태 머신

### 6.1 화면 흐름 (선형)
```
회원가입(+개인정보 동의) → 로그인 → 사진 입력(필수) →
고정 질문 6개 → 반응형 질문 3개 → 페르소나 후보 3개 중 1개 선택 → 결과 카드/개인 페이지
```

### 6.2 진행 상태 머신 (서버가 단일 소스)
```
[계정없음] ─가입→ [registered] ─페르소나 선택→ [completed]
                      │                              │
               중간 이탈=진행 미저장           1인 1카드, 재시도 불가
                      │                              │
            로그인 시 사진부터 처음          로그인 시 결과 카드로
```
- **부분 진행 저장 안 함** — 도중 이탈하면 다음 로그인 때 사진부터 다시.
- **완료자는 어느 경로로 와도 결과로 리다이렉트**(진입 게이트가 상태 조회 후 분기).

## 7. AI 오케스트레이션 (개념)

```
[Q1~6 + 반응형 Q7~9 응답]
        │
        ▼
[응답 해석 (chat)] → [페르소나 후보 3개 생성 (chat)]
        │
        ▼  ◀── 학생이 1개 선택
─────────── 카드 생성 잡 큐잉 ───────────
        │  jobs(generate_card) INSERT → 프론트는 폴링
        ▼ (인-프로세스 워커)
[이미지 프롬프트 (chat)] → [카드 이미지 생성 (image, 얼굴 유지 image-to-image)]
        │
        ▼
[카드 저장(S3 + DB) + 영구 공유 토큰 발급] → 잡 done → 결과 화면
```

### 7.1 동기 / 비동기 경계
| 작업 | 처리 | 이유 |
|---|---|---|
| 응답 해석·후보 생성 | HTTP 동기 | 짧음(수~십수 초), 학생 대기 |
| 카드 이미지 생성 | **잡 큐 + 폴링 워커** | 길음(30~60초), timeout·새로고침 대비 |

### 7.2 어댑터 원칙
- 코드는 모델명을 직접 호출하지 않고 **목적(purpose)** 으로 호출 → 모델 매핑은 환경변수.
- 동시성은 세마포어로 제한. **진짜 상한은 OpenRouter rate limit.**

## 8. 인증 / 인가

| 토큰 | 용도 | 만료 |
|---|---|---|
| 학생 세션 | 질문 진행 API | 단기(수 시간) |
| 카드 공유(영구) | QR/개인 페이지 진입 | 무기한(revoke 시 차단) |
| 단기 공유 | 부모/친구 공유 | 24h |
| 운영자 세션 | 부스 스캔·적립 | 반일 |
| 관리자 세션 | 대시보드·관리 | 반일 |

- 권한 가드는 FastAPI 의존성으로 주입(`current_student/operator/admin`).
- 운영자/관리자 액션은 감사로그(`ops.audit_logs`)에 기록.

## 9. 배포 토폴로지

```
GitHub(main push)
   │  Actions: 빌드 → (SSH 또는 이미지 레지스트리)
   ▼
Lightsail 인스턴스 (2GB/2vCPU/60GB/3TB, Dual-stack)
   ├─ Caddy: 80/443, 자동 HTTPS(Let's Encrypt), reverse_proxy → app:8000
   └─ FastAPI 컨테이너: 앱 + 워커 (8000은 외부 비공개)
        ├─→ Supabase Postgres  (직접연결 :5432, IPv6)
        ├─→ AWS S3            (photos/ cards/, presigned URL)
        └─→ OpenRouter        (chat + image)
```
- 방화벽: 22(내 IP만)·80·443만 공개, 8000 비공개.
- 시크릿: 인스턴스 `.env`(JWT·Supabase·S3 IAM·OpenRouter 키). Lightsail은 EC2 instance role이 없어 **IAM 사용자 키** 사용(두 버킷만 허용하는 최소권한).
- 2GB 안전판: 스왑 + 워커 동시성 제한 + (필요 시) 이미지 빌드 외부화.

## 10. 개인정보 / 보안

- **사진 영구 보관**(A-4) — 회원가입 동의·면책에 *영구 보관 및 이용 목적* 명시, 만 14세 미만은 **법정대리인 동의**(가정통신문). 삭제 요청 절차는 유지.
- 파일 접근은 **presigned URL만**(프라이빗 버킷, 직접 URL 불가).
- schema 단위 권한 격리(§5.2), 운영자 토큰의 PII 접근 차단.
- 비밀번호 해시(bcrypt), HTTPS 강제, CORS는 프론트 도메인만, 감사로그.

## 11. 부하 / 확장 전략

| 상황 | 동작 |
|---|---|
| 가벼운 요청 폭주 | 단일 인스턴스 asyncio가 동시 수백 처리. 병목은 Supabase 컴퓨트 → 활성기간 Pro로 완화 |
| 카드 생성 폭주 | jobs 큐로 줄 세워 처리(안 죽음). 큐 임계 초과 시 429 백프레셔 |
| 이미지 조회 폭주 | S3/CloudFront가 직접 서빙 → 앱·Lightsail 전송 미소비 |
| 진짜 천장 | OpenRouter 이미지 rate limit |

- 프로젝트 특성상 카드는 **배치 생성**(7월 말), 행사(10월)는 주로 **조회** → 행사 당일 앱 부하 작음.
- 스케일업: 평시 작게 → 배치/행사 시점만 인스턴스 플랜·동시성 상향 → 이후 복귀.
