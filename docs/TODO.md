### [ ] 미리보기가 실제 업로드와 다르다

**위치**: `frontend/app/signup/photo/page.tsx:160-161` (미리보기), `:66-71` (갤러리 경로)

**문제**: 미리보기는 `bg-cover bg-center`로 **가운데를 원형으로 잘라 보여주는데**,
갤러리 선택 경로는 `CropStep`을 건너뛰어 **원본을 그대로 업로드한다.**
학생은 "얼굴 잘 들어갔네" 하고 확인하지만 AI는 잘리지 않은 단체사진을 받는다.

**할 일**: 갤러리 경로에도 `CropStep`을 적용해 미리보기와 업로드 결과를 일치시킨다.
`frontend/app/(tabs)/profile/[id]/page.tsx:111`의 사진 수정 경로도 동일하게 적용.

**자동 중앙 크롭으로 때우지 말 것.** 가운데를 기계적으로 자르면 얼굴이 중앙에 없는 사진에서
오히려 얼굴이 잘려 나간다. `CropStep`은 이미 드래그·핀치 줌·줌 슬라이더로 영역 선택을 지원하므로
(`components/photo/CameraCapture.tsx:277-482`), **학생이 직접 크롭 영역을 고르게** 한다.

### [ ] 학생 사진 업로드가 `inspect_image()`를 거치지 않는다

**위치**: `backend/app/services/auth_service.py:212`

**문제**: `backend/app/core/images.py`의 `inspect_image()`가 디코드 무결성·해상도를 확인해 주는데,
이 함수는 *AI 생성 이미지* 검사에만 쓰이고 **학생 업로드 경로는 거치지 않는다.**
라우터(`students.py:32-46`)도 MIME 타입과 10MB만 본다 — 40×40 아이콘도, 잘린 손상 파일도 통과한다.

**할 일**: `attach_photo`에서 `inspect_image()`를 호출한다. Pillow는 이미 의존성이라 추가 비용 없음.

### [ ] 사진 없는 학생 카드에 낯선 사람 얼굴이 들어간다

**위치**: `backend/app/services/persona_pipeline.py:29-31`

```python
if photo is not None:
    return await ai.edit_image(...)      # 본인 얼굴 기반
return await ai.generate_image(...)      # 사진 없이 프롬프트만으로 생성
```

**문제**: 프롬프트는 여전히 *"the SAME person as the input photo"*(`core/prompts/image_prompt.py:15`)인데
참조할 사진이 없다. AI는 **아무 상관 없는 낯선 사람의 실사 얼굴**을 그린다.
→ 사진 없는 학생의 대원증에 **모르는 사람 얼굴이 박혀 나간다.**

**할 일**: 사진이 없으면 낯선 사람 실사 얼굴 대신 **캐릭터 얼굴**이 나가게 한다.
`_portrait`의 else 분기를 **미리 만들어 둔 정적 캐릭터 이미지**로 교체하는 쪽을 권한다
(AI 호출 없음, 비용 0, **결과가 예측 가능해서 업로드 화면에 실물을 그대로 보여줄 수 있다**).
캐릭터 프롬프트로 생성하는 방식도 가능하나 매번 달라져 미리 보여줄 수 없다.

캐릭터는 **의도적으로 밋밋하게**(기본 실루엣·단색 아바타) 만든다 — 멋지면 일부러 사진을 안 올린다.
