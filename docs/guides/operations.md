# 운영 런북

행사 당일과 그 직전에 보는 문서. 배포 방법은 [`deployment.md`](deployment.md),
용량 산정 근거는 [`../notes/2026-08-08-행사-부하-용량-점검.md`](../notes/2026-08-08-행사-부하-용량-점검.md).

> **이 문서는 뼈대다.** 확인된 내용만 적었고, 아직 정하지 않은 것은 그렇다고
> 표시했다. 추측으로 채우지 않는다 — 런북에 틀린 절차가 있으면 없느니만 못하다.

## 한눈에

| 항목 | 값 |
|---|---|
| API 헬스체크 | `https://api.cnu-likelion.kr/healthz` |
| 관리자 콘솔 | `/admin` (로그인: `/admin/login`) |
| 운영진 콘솔 | `/operator` (로그인: `/operator/login`) |
| 배포 트리거 | `production` 브랜치에 `backend/**` push |
| 롤백 | **없음** — CD에 롤백 단계가 없다 |
| 모니터링·알림 | **없음** — 장애를 육안으로 확인해야 한다 |

마지막 두 줄이 이 운영의 가장 큰 약점이다. 행사 중 문제가 생기면 **사람이
먼저 알아차려야 하고, 되돌릴 자동 장치가 없다.**

## 행사 중 배포 동결

**행사 기간에는 `production` 머지를 하지 않는다.**

`backend/**`가 push되면 즉시 자동 재배포되고, 새 컨테이너가 뜨는 데 실패하면
**API 전체가 죽는다.** 롤백 단계가 없어 사람이 SSH로 들어가 고칠 때까지
복구되지 않는다.

- 긴급 수정이 불가피하면: 현장 인원에게 먼저 알리고, 헬스체크를 지켜보면서 머지한다.
- 사전에 GHCR 이미지 프리빌드를 해두면 빌드 실패 위험이 준다
  (§7.2-8, 아직 미적용).

## 장애 시 확인 순서

증상이 무엇이든 **위에서부터** 확인한다. 아래로 갈수록 원인이 깊다.

**1. API가 살아 있나**

```bash
curl -i https://api.cnu-likelion.kr/healthz
```

- 200이 아니면 → 2번
- 200인데 화면이 안 되면 → 4번 (프론트/네트워크)

**2. 컨테이너 상태**

```bash
ssh <배포서버>
cd <DEPLOY_PATH>/backend
docker compose -f docker-compose.yml -f compose.prod.yml ps
docker compose -f docker-compose.yml -f compose.prod.yml logs --tail=100 app
```

재시작을 반복하고 있으면 → 3번.

**3. 환경변수 누락 (재시작 루프의 최빈 원인)**

`APP_ENV=production`에서 필수 변수가 없거나 예시값이면 앱이 기동을 거부한다.

```bash
cd <DEPLOY_PATH>/backend
grep -E '^(APP_ENV|JWT_SECRET|JWT_CARD_SHARE_SECRET|ADMIN_PASSWORD|OPERATOR_PASSWORD|FRONTEND_ORIGIN)=' .env
```

값이 `change-me-*`이거나 줄이 아예 없으면 그게 원인이다.
→ 상세: [`deployment.md`](deployment.md) "운영 필수 변수"

**4. 프론트엔드 / 네트워크**

- Vercel 배포 상태 확인
- 현장 와이파이 — 용량 점검 문서가 지목한 최대 리스크다
  (부스 300개·1만 명 규모에서 전시장 인터넷은 사실상 마비된다)

**5. DB (Supabase)**

- 대시보드에서 커넥션 수·용량 확인
- Free 플랜이면 한도에 걸렸을 수 있다 → 용량 점검 문서 §3

## 자주 나오는 증상

| 증상 | 먼저 볼 것 |
|---|---|
| 관리자 화면이 "학생이 없습니다"로 빈다 | 토큰 만료일 수 있다. 재로그인해본다 |
| 학교·반을 바꿨는데 이전 명단이 남는다 | 전환 요청 경합. 새로고침으로 우회 |
| 부스 QR을 카메라로 찍으면 안 열린다 | `FRONTEND_ORIGIN` 확인. 인쇄물은 회수 불가이므로 인쇄 전 반드시 실물 테스트 |
| 사진이 안 보인다 | presigned URL 만료. 새로고침 시 재발급된다 |
| 앱 전체 500 | 3번(환경변수) → DB 마이그레이션 미적용 순으로 확인 |

## DB 마이그레이션

**CI·CD가 자동 적용하지 않는다.** 사람이 Supabase SQL Editor에 직접 실행한다.

**반드시 코드 배포보다 먼저 적용한다.** 새 컬럼을 참조하는 코드가 먼저 나가면
`asyncpg.UndefinedTableError`로 500이 나고, 화면에는 원인을 알 수 없는
"요청을 처리하지 못했어요."만 보인다.

→ 상세: [`deployment.md`](deployment.md) "DB 마이그레이션"

## 아직 정하지 않은 것

행사 전에 채워야 한다. **비워둔 채로 행사에 들어가지 않는다.**

- [ ] 장애 시 연락 체계 — 누가 누구에게, 어떤 수단으로
- [ ] 현장 대응 인원과 각자의 접근 권한 (SSH·Supabase·Vercel·OpenRouter)
- [ ] 배포 동결 기간의 정확한 시작·종료 시각
- [ ] 사진 업로드 실패 시 현장 대체 절차
- [ ] 백업·복구 절차와 마지막 백업 시점 확인 방법
- [ ] 업타임 모니터링 도입 여부 (용량 점검 §7.3 P1)
