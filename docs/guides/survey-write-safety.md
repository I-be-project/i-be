# 설문 재시도와 사진 교체 저장

## 적용 순서

1. `backend/supabase/migrations/0015_survey_requests_and_photo_cleanup.sql`을 대상 DB에 적용한다.
   두 테이블을 추가하며 기존 학생·세션·답변을 변경하지 않는다.
2. 백엔드를 재시작한 뒤 프론트엔드를 배포한다. `/restart` 요청 형식이 바뀌므로
   열려 있던 브라우저는 새로고침한다. 이전 형식은 422로 거부되어 결과를 삭제하지 않는다.

## 저장 규칙

- 최초 답변은 localStorage에 영속화한 `requestId`로 재전송한다. 서버는 학생 행을
  `FOR UPDATE`로 잠그고 요청 키·세션·답변을 하나의 트랜잭션에 저장한다.
- 재시작은 고유 `requestId`와 프로필의 `completed_session_id`를 함께 보낸다.
  동일 요청은 기존 새 세션을 반환한다. 다른 재시작이 먼저 처리됐거나 이전 완료 세션이
  바뀌었으면 409로 거부한다. 확인된 재시작에서만 이전 미완료 세션을 `abandoned`로 바꾸고,
  완료 결과를 삭제하고 새 세션을 생성한다. 하나라도 실패하면 전체 롤백한다.
- 삭제된 세션의 요청 키는 `session_id=NULL`로 남아 오래된 첫 저장을 차단한다.
  답변 저장/완료도 같은 학생 잠금을 사용한다. `session_completed`만 완료 응답 유실로
  취급하고, `session_superseded`·일반 409는 성공으로 표시하지 않는다.
- 최초 사진도 고유 파일명을 쓴다. 사진 경로가 업로드 시작 당시와 같은 경우만 DB를
  교체한다(CAS). 충돌한 새 파일과 교체한 이전 파일은 삭제 큐에 기록한다.
- 사진 정리 워커는 DB가 활성화된 앱에서 60초마다 동작한다. 현재 학생 레코드에서
  참조하는 파일은 삭제하지 않는다. 삭제 실패 시 큐를 유지한다. DB 커밋 응답이 유실된
  경우도 즉시 파일을 지우지 않고 이 참조 확인을 거친다. DB 자체가 계속 불통이라
  정리 예약도 실패하면 `사진 정리 예약 실패` 로그의 키로 별도 복구가 필요하다.

기존에 쌓인 미완료 세션이나 미사용 S3 파일을 일괄 삭제하는 마이그레이션은 포함하지 않는다.
