# 학교·반·학생을 전환하면 이전 대상의 데이터가 화면에 남는다

관리자 좌석표와 학생 상세에서 **같은 증상이 다섯 번** 나왔다. 셀렉터로 대상을
바꿨는데 이전 대상의 데이터가 새 이름 아래 그대로 보이는 것이다.

증상이 같아서 한 문제로 보이지만 **원인은 두 갈래**다. 처방이 다르므로 나눠 적는다.

## 증상

**A. 요청 경합** (`4419ab5` · `0cda678` · `519f25b`)

- 학교 셀렉터를 빠르게 두 번 바꾸면 이전 학교의 학생 명단이 남는다.
- 학교를 바꿨는데 로딩 스켈레톤이 영원히 안 걷힌다.

**B. 렌더 타이밍** (`d59c209` · `20665a3`)

- 학생 상세를 전환하면 새 학생 이름 아래 **이전 학생의 사진·설문 결과**가
  잠깐 보인다.

## 원인

**A. 응답 도착 순서 ≠ 요청 순서**

`fetch` 응답은 요청한 순서대로 오지 않는다. A(느림) → B(빠름) 순으로 보내면
B가 먼저 그려지고 **A가 나중에 도착해 덮어쓴다.**

세 커밋에 걸쳐 조금씩 깁게 된 이유는 가드에 구멍이 세 개 있었기 때문이다.

| 커밋 | 구멍 |
|---|---|
| `4419ab5` | 세대 검사가 아예 없었다 |
| `0cda678` | 상위 요청이 하위 목록을 **비우기만 하고 세대를 올리지 않아**, 이미 날아간 하위 요청이 자기 세대 검사를 통과해 옛 데이터를 커밋했다 |
| `519f25b` | 세대를 올릴 때 **로딩 플래그를 안 내려서**, 무효화된 요청의 `finally`가 세대 불일치로 플래그를 못 끄고 스켈레톤이 영구히 남았다 |

`0cda678`·`519f25b`는 **가드 자체가 만든 2차 버그**다. 무효화는 "버린다"와
"버렸다고 알린다"가 짝이어야 하는데 앞쪽만 했다.

**B. prop이 바뀐 첫 렌더에서 초기화 `useEffect`가 아직 안 돌았다**

React는 prop 변경 → 렌더 → `useEffect` 순으로 돈다. 그래서 `student` prop이
바뀐 **첫 렌더 시점에는 이전 학생의 `detail`이 그대로 state에 있다.**
`loadingDetail`만 보고 판단하면 이 한 프레임에서 옛 데이터가 새 이름 아래 나온다.

## 해결

**A** — 요청마다 세대 번호를 발급하고, 커밋 직전에 최신 세대인지 확인한다.
무효화할 때 **하위 요청의 세대도 함께 올리고 로딩 플래그도 같이 내린다.**

→ `frontend/components/console/SeatingView.tsx` (`classProgressRequestId`,
`classStudentsRequestId`)

```ts
const requestId = ++classStudentsRequestId.current;
// ...
if (requestId !== classStudentsRequestId.current) return;  // 더 새 요청에 밀림
```

**B** — 로딩 플래그가 아니라 **데이터의 소속**을 확인한다.

→ `frontend/components/console/StudentDetailSidebar.tsx`

```ts
// loadingDetail만으로는 부족하다 — 첫 렌더에서 아직 false다
detail?.id !== student.id || loadingDetail
```

## 교훈

**전환 가능한 UI에서는 로딩 플래그를 믿지 말고 데이터의 소속을 확인한다.**

`loading === false`는 "표시해도 된다"를 뜻하지 않는다. "지금 요청이 없다"만
뜻한다. 화면에 그릴지 판단하는 근거는 **이 데이터가 지금 선택된 대상의
것인가**여야 한다.

새로 "셀렉터 + 비동기 로딩" 조합을 만들 때 체크리스트:

- [ ] 요청마다 세대 번호를 발급하는가
- [ ] 커밋 직전에 세대를 검사하는가 (`finally`의 로딩 해제 포함)
- [ ] 상위를 전환할 때 **하위 요청의 세대도** 올리는가
- [ ] 세대를 올릴 때 **로딩 플래그도 함께** 내리는가
- [ ] 렌더 조건이 `loading`이 아니라 `data.id !== selected.id`를 보는가

마지막 두 항목이 `519f25b`·`20665a3`에서 놓친 것이다. 앞의 세 개만 챙기면
같은 자리에서 또 터진다.
