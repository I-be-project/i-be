# FRONTEND_ORIGIN이 틀려도 앱이 조용히 떴다

## 배경

부스 QR 코드는 `FRONTEND_ORIGIN`을 base로 `/b/<code>` 링크를 만든다. 이 값이
틀리면 **인쇄된 QR이 전부 못 쓰게 된다** — 행사 현장에서 되돌릴 수 없는 종류의
실패다.

그런데 이 값에 대한 검증이 두 군데 다 없었다.

| 커밋 | 잘못된 값 | 결과 |
|---|---|---|
| `5bfddbf` | `i-be.vercel.app` (스킴 없음) | 기본 카메라 앱이 링크로 인식 못 함 |
| `8e91330` | 기본값 `localhost:3000` (dev 서버는 4000) | 로컬에서 만든 QR을 열 수 없음 |

둘 다 **앱은 정상 기동했다.** 문제는 QR을 찍어보기 전까지 드러나지 않는다.

## 근거

값이 없거나 형식이 틀렸을 때 **기동을 막는 편이 안전하다**고 판단했다.

이 프로젝트에는 이미 같은 판단의 선례가 있다 — `JWT_SECRET`·`ADMIN_PASSWORD`
등이 예시값이면 `APP_ENV=production`에서 기동을 거부한다. `config.py`의 주석이
그 이유를 적어두고 있다:

> 조용히 뜨면 공개된 플레이스홀더로 학생·관리자 토큰을 서명하게 되므로,
> 배포를 실패시켜 헬스체크에서 잡히게 하는 편이 안전하다.
> FRONTEND_ORIGIN도 같은 이유다 — 부스 QR 링크의 base라, localhost가 박힌
> 인쇄물이 현장에 나가면 되돌릴 수 없다.

**버린 대안**: 기동 시 경고 로그만 남기기. 배포 로그를 아무도 안 보므로
경고는 없는 것과 같다. CD 헬스체크가 잡아주는 실패가 훨씬 강한 신호다.

## 조치

`APP_ENV=production`에서 절대 URL인지 검사하고, 아니면 기동을 거부한다.

→ `backend/app/config.py:157`

```python
if not self.frontend_origin.startswith(("http://", "https://")):
    raise ValueError(
        "APP_ENV=production에서 FRONTEND_ORIGIN은 http:// 또는 https://로 "
        "시작하는 절대 URL이어야 합니다."
    )
```

로컬 기본값은 프론트 dev 서버 포트(4000)에 맞췄다 — `next dev -p 4000`.

→ 테스트: `backend/tests/test_config_production_guard.py`

## 주의사항

**가드를 추가하는 커밋은 서버 `.env`보다 먼저 배포되면 안 된다.**

`app = create_app()`이 모듈 임포트 시점에 실행되므로, 값이 없으면 새 컨테이너가
뜨자마자 재시작을 반복한다. **CD 워크플로에 롤백 단계가 없어서** 부스 기능만이
아니라 **API 전체가** 사람이 SSH로 들어갈 때까지 죽는다.

순서를 지킨다:

1. 서버 `backend/.env`에 값 추가
2. PR을 `production`에 머지
3. `https://api.cnu-likelion.kr/healthz` 확인

`backend/**` 변경은 push 즉시 자동 배포되므로 1번을 건너뛸 여지가 없다.
같은 함정이 `OPERATOR_PASSWORD` 도입 때도 있었다 → `guides/deployment.md`의
"운영 필수 변수" 절에 기록돼 있다.

**되돌릴 수 없는 산출물을 만드는 설정값은 가드 대상이다.** QR 인쇄물, 발송된
링크, 생성된 이미지처럼 배포 후 회수가 불가능한 것을 만드는 값은 기동 시점에
검증한다. 화면에서 확인 가능한 값과는 다르게 다뤄야 한다.
