# 사진 업로드 품질 개선 — 회의안

작성일: 2026-08-15 · 상태: 논의용 초안

학생이 올리는 사진이 본인 얼굴이 아니거나 쓸 수 없는 상태다.
사진은 프로필 이미지가 아니라 **AI가 "28살의 너"를 그리는 원본 입력**이라 (`core/prompts/image_prompt.py:15`),
품질이 낮으면 카드가 통째로 무너진다.

**전제**: 업로드 시점 AI 이미지 생성 호출 금지 · 얼굴 자동 검출 불가.

---

## 문제

### 1. 왜 진짜 얼굴이어야 하는지 학생이 모른다

업로드 화면 문구가 보상이 아니라 부담을 말한다. (`signup/photo/page.tsx:129-138`)

> "대원증에 붙일 사진을 담아줘 / 한마당에서 **친구들에게 보여줄** 너만의 표식이야"

10대가 읽는 건 *"내 얼굴이 배지에 박히고 친구들이 본다"*. 이 프레임에서는 밈 사진이 합리적인 선택이 된다.
진짜 보상("네 얼굴로 28살의 너를 그려준다")은 화면 어디에도 없다.
게다가 카드는 행사 당일에야 공개돼서 (`explore/pending-card/page.tsx:13`) 앱 안에서 결과를 볼 기회가 한 번도 없다.

### 2. 밈을 올리기가 너무 쉽다

"사진 촬영"과 "갤러리에서 선택" 버튼이 같은 크기다. (`signup/photo/page.tsx:177-196`)
밈·캐릭터는 거의 전부 갤러리에서 온다. 지금 찍은 사진은 정의상 본인 얼굴일 확률이 훨씬 높다.

### 3. 갤러리 사진은 크롭 없이 올라가고, 미리보기가 거짓말한다

- 카메라는 원형 가이드 + 720×720 크롭을 거치지만, **갤러리는 원본 그대로 업로드**된다 (`:66-71`)
- 미리보기는 가운데를 원형으로 잘라 보여준다 (`:160-161`) → 학생은 "얼굴 잘 들어갔네" 하고 확인하지만 **AI는 잘리지 않은 단체사진을 받는다**
- 프로필 사진 수정(`profile/[id]/page.tsx:111`)도 같다

### 4. 사진 없는 학생 카드에 낯선 사람 얼굴이 들어간다

사진이 없으면 프롬프트만으로 초상을 생성하는데 (`persona_pipeline.py:29-31`),
그 프롬프트가 여전히 *"the SAME person as the input photo"* 다. 참조할 사진이 없으니 **모르는 사람의 실사 얼굴**이 나온다.

### 5. 문제 규모를 측정할 방법이 없다

관리자 화면에 사진을 한눈에 훑어볼 수단이 없어서, 지금 몇 %가 문제인지 아무도 모른다.
뭘 고치든 효과를 확인할 수 없다.

## 해결방안

| 방안 | 해결하는 문제 | 비용 |
|---|---|---|
| **문구를 "네 얼굴로 28살의 너를 그려줄게"로 바꾸고, 완성 카드 예시를 보여준다** | 1 | 프론트만 |
| **"사진을 안 올리면 이 캐릭터가 들어가"를 미리 알린다** (+ 폴백을 캐릭터로 교체) | 1, 4 | 프론트 + 백엔드 소폭 |
| **좋은 예 / 나쁜 예를 O·X 썸네일로 보여준다** | 1, 2 | 프론트만 |
| **"촬영"을 기본 버튼으로, "갤러리"는 작은 링크로 내린다** | 2 | 프론트만 |
| **갤러리에도 크롭을 적용한다** (미리보기 = 실제 업로드) | 3 | 프론트만 |
| **설문이 끝난 뒤 사진 확인·교체 단계를 넣는다** (건너뛰기 허용) | 1 | 프론트, 화면 하나 |
| **밝기·해상도·선명도를 검사해 경고한다** (막지 않음) | 3 | 프론트 + 백엔드 소폭 |
| **관리자 사진 그리드 뷰를 만든다** | 5 | 백엔드 + 관리자 UI |

### 만들 때 주의할 것

**캐릭터를 선택지로 주면 안 된다.**
"캐릭터로 할래" 버튼을 만들면 쉬운 탈출구가 되어 사진 비율이 오히려 떨어진다.
"안 하면 이렇게 된다"는 **결과로만** 노출한다.
그리고 **캐릭터를 멋지게 만들면 안 된다** — 기본 실루엣·단색 아바타 수준으로 밋밋해야 "내 카드만 밋밋하네"가 작동한다.
결과를 미리 보여주려면 매번 달라지면 안 되므로, AI 생성이 아니라 **미리 만든 정적 이미지 몇 종**을 쓴다.

**자동 중앙 크롭으로 때우면 안 된다.**
얼굴이 중앙에 없는 사진에서 오히려 얼굴이 잘린다.
`CropStep`이 이미 드래그·핀치 줌을 지원하므로 그대로 쓴다 (`CameraCapture.tsx:277-482`).
학생이 얼굴을 원에 맞추는 행위 자체가 좋은 사진을 고르게 만드는 유도 장치다.

**밝기·해상도 경고는 막지 말고 경고만.**
어두운 데서 찍은 진짜 학생이 갇히면 안 된다. "이 사진 좀 어두워. 이대로 할까?" + 계속하기.
그리고 이 검사는 **"얼굴이 아님"을 전혀 못 잡는다** — 잘 찍은 캐릭터 일러스트는 100% 통과한다.

**사진 요청 시점은 옮기지 않고 단계를 추가한다.**
지금은 사진이 관문이라 (`flow.ts:103`) 미업로드가 구조적으로 없다. 설문 뒤로 아예 옮기면 사진 없이 이탈하는 학생이 새로 생긴다.
받는 건 지금 자리에서 그대로 받고, 몰입도가 최고인 설문 직후에 **교체 기회만** 준다.

## 하는 순서

1. **관리자 사진 그리드** — 측정 수단이 먼저. 없으면 나머지가 전부 감으로 하는 일이 된다
2. **문구 + 캐릭터 예고 + 좋은 예/나쁜 예 + 갤러리 강등 + 크롭** — 대부분 프론트만, 한 번에
3. **설문 후 확인·교체 단계**
4. **밝기·해상도 경고**

## 회의에서 정할 것

1. **학생이 얼굴을 안 올리는 진짜 이유는?** (쪽팔림 / 개인정보 걱정 / 장난) — **현재는 추측이다.** 개인정보 걱정이라면 "누가 보는지" 명시하는 방안이 추가로 필요하다
2. **"얼굴이 아닌 사진은 기계로 못 막는다"를 받아들이는가?** 받아들이면 관리자 그리드가 선택이 아니라 필수가 된다
3. **행사까지 남은 기간은?** 백엔드를 건드리는 방안의 가능 여부가 갈린다
4. **관리자 사진 검토를 누가, 언제 하는가?**
