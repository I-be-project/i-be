# 사진 업로드 품질 개선 — 회의안

작성일: 2026-08-15 · 상태: **논의용 초안**

**요약** — 학생이 본인 얼굴 대신 밈·캐릭터를 올린다. 원인은 *보상을 안 알려주고*, *갤러리를 너무 쉽게 열어주고*, *결과를 볼 기회가 없어서*다.
→ 1차로 프론트 5개(A·K·J·F·B)를 치고, 그 전에 측정 수단(G1)부터 만든다.

## 제약 (확정)

- **런타임 AI·이미지 생성 API 호출 금지** → 업로드 시점 초상 미리보기 불가
- **얼굴 검출 비현실적** → "얼굴인지"를 기계가 판단하는 안 불가

---

## 1. 문제

사진은 프로필 이미지가 아니라 **AI가 "28살의 너"를 그리는 원본 입력**이다. 품질이 낮으면 카드가 통째로 무너진다.

| 증상 | 기계가 잡나 | 대응 |
|---|---|---|
| **얼굴이 아님** — 밈·캐릭터·풍경 | **아니오** | 설득·유도·사람의 눈 |
| **얼굴인데 쓸 수 없음** — 어둡다·작다·흐리다 | 예 | 픽셀 통계로 경고 |

**합의할 것: "얼굴이 아님"은 기계로 못 막는다.** 잘 찍은 캐릭터 일러스트는 어떤 안으로도 안 걸러진다.

---

## 2. 언제 사진을 요구할 것인가

```
현재:  회원가입(1/2) → 사진(2/2) → 설문 Q1~9 → 카드 (행사 당일 공개)
                          ↑ 여기
```

| | **A. 가입 폼 안** | **B. 가입 직후 (현재)** | **C. 설문 이후** |
|---|---|---|---|
| 몰입도 | 최저 | 낮음 | **최고** |
| 사진 용도를 아는가 | 모름 | 모름 | **안다** |
| 미업로드 이탈 | 없음 | 없음 (관문) | **발생** |
| 예상 품질 | 최악 | 나쁨 | **최고** |

- **A 기각** — 가입 폼이 이미 무겁고, 백엔드도 가입/사진을 분리해 뒀다 (`auth.py:30`)
- **B** 완주율 최고 / 품질 나쁨 · **C** 품질 최고 / 완주율 위험

### 결론 — 하이브리드 (= 안 T)

```
회원가입 → 사진 [필수, 현행 유지] → 설문 Q1~9 → [NEW] 사진 확인·교체 → 카드
                  ↑                                  ↑
           완주율 보장(관문)                 품질 회수(몰입도 최고)
```

확인 단계는 **건너뛰기 허용**. 사진은 이미 받았으니 잃을 게 없다.

- 제약으로 안 D가 빠져 사라진 **자기교정 기회를 API 없이 되살리는 유일한 수단**
- 프로필 화면에 사진 수정이 이미 있지만 **유도 동선이 없어 아무도 안 간다** — 이 단계가 그 역할
- `flow.ts`에 화면 하나 추가. 가드 재설계 불필요
- **더 가벼운 대안**: `pending-card` 화면에 "사진 바꾸기" 링크만 얹기

---

## 3. 안

> **S** 프론트만 · **M** 구조 변경/백엔드 소폭 · **L** 백엔드 + 관리자 UI

| 안 | 내용 | 비용 | 핵심 |
|---|---|---|---|
| **A** | 문구 재프레임 + **완성 카드 예시 노출** | S | 말로 쓰지 말고 결과를 보여준다. 예시는 미리 만든 정적 에셋 |
| **K** | **"안 올리면 캐릭터로 나간다"를 미리 알린다** | S~M | 폴백 결함도 같이 고침. 아래 주의 참고 |
| **J** | 좋은 예 / 나쁜 예 O·X 썸네일 4장 | S | **"캐릭터 안 됨"을 명시하는 유일한 안** |
| **F** | "촬영"을 기본 버튼, "갤러리"는 작은 링크로 | S | **밈은 거의 전부 갤러리에서 온다** |
| **B** | 갤러리에도 `CropStep` 적용 (미리보기 = 실제) | S | **자동 중앙 크롭 금지, 학생이 직접 선택** |
| **T** | 설문 이후 사진 확인·교체 단계 (2절) | S~M | 건너뛰기 허용 |
| **I** | 픽셀 통계(해상도·밝기·선명도)로 **경고만** | S~M | **B가 전제.** "얼굴 아님"은 못 잡음 |
| **I-a** | 백엔드 `attach_photo`에 `inspect_image()` 연결 | S | 단독 도입 가능. Pillow 이미 의존성 |
| **G1** | 관리자 **사진 그리드 뷰** | M | **유일한 측정 수단.** 밈은 격자로 보면 한눈에 튄다 |
| **G2** | 재촬영 요청 발송 | L | G1 + 현장 호출로 대체 가능 |
| **H** | 개인정보 안심 문구 | S | 영구 보관이라 **"지워진다" 약속 불가** |

### 설계 주의

**안 K — 캐릭터를 선택지로 주면 안 된다.**
- "캐릭터로 할래" 버튼 = 쉬운 탈출구. **결과로만** 노출한다 ("안 하면 이렇게 돼")
- **캐릭터를 멋지게 만들면 안 된다.** 기본 실루엣·단색 아바타 수준으로 밋밋하게.
  "내 카드만 밋밋하네"가 작동 원리다

**안 K — 폴백 구현 방식**

| | (a) 정적 캐릭터 에셋 | (b) 캐릭터 프롬프트로 생성 |
|---|---|---|
| AI 호출 | 없음 | 있음 |
| **결과 예측** | **가능** | 불가 (매번 다름) |
| 다양성 | 낮음 | 높음 |

**(a) 추천** — "안 올리면 이게 들어가"를 미리 보여주려면 결과가 예측 가능해야 한다.

**안 B — 자동 중앙 크롭으로 때우지 말 것.** 얼굴이 중앙에 없는 사진에서 오히려 얼굴이 잘린다.
`CropStep`이 이미 드래그·핀치 줌을 지원한다. 학생이 얼굴을 원에 맞추는 행위 자체가 유도 장치다.

**안 I — 막지 말고 경고만.** 어두운 데서 찍은 진짜 학생이 갇히면 안 된다.

## 4. 추천 순서

| 순서 | 안 | 이유 |
|---|---|---|
| **0차 · 측정** | **G1** | 없으면 나머지가 전부 감으로 하는 일이 된다 |
| **1차 · 즉시** | **A + K + J + F + B** | 대부분 프론트만. "얼굴 카드 vs 밋밋한 캐릭터" 대비로 동기 생성 |
| **2차** | **T** | 자기교정 기회 복원 |
| **3차** | **I-a → I** | I는 B가 깔린 뒤라야 저렴 |
| **조건부** | **H · G2** | H는 거부 이유가 "개인정보 걱정"일 때 |

## 5. 제외된 안

| 안 | 내용 | 사유 |
|---|---|---|
| **D** | 업로드 직후 AI 초상 미리보기 | 런타임 이미지 생성 금지 |
| **E** | 자동 얼굴 검출 게이트 | 얼굴 검출 비현실적. 오판정 시 진짜 학생이 갇힘 |

**대가**: "얼굴이 아님"을 자동으로 거를 수단이 **하나도 없다.** 설득·유도·사람의 눈뿐.

## 6. 회의에서 결정할 것

1. **사진 요청 시점을 하이브리드(안 T)로 갈 것인가?**
2. **학생이 얼굴을 안 올리는 진짜 이유는?** (쪽팔림 / 개인정보 걱정 / 장난) — **현재는 추측**
3. **"얼굴 아님은 기계로 못 막는다"를 받아들이는가?** → 받아들이면 G1이 필수
4. **행사까지 남은 기간은?** → 백엔드 건드리는 안(T·G1·G2·I-a) 가능 여부
5. **G1의 사진 검토를 누가, 언제 하는가?**
