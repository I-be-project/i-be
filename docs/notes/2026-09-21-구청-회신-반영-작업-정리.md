## 2. 개발 작업

### P0 — 결정이 먼저 필요한 것 (9/22~9/24)

| # | 작업 | 내용 | 규모 |
|---|---|---|---|
| D-1 | **추천 구조 확정** | 구청안 수용 여부. 수용 시: `Persona`에 `required_competencies: list[str]` 3개 추가 → 페르소나 프롬프트가 10개 vocabulary 중 3개를 고르도록 수정 → 저장(generated 스키마 컬럼 추가) | 결정 0.5일 + 구현 1일 |
| D-2 | **역량부스 추천 API** | C존 10개 부스는 10개 역량과 1:1이다(스피치ON=의사소통 … 성장ON=계획성). 즉 **추천 = 필요 역량 3개 → C존 부스 3개 매핑**이라 별도 추천 엔진이 필요 없다. `GET /api/booths/recommended` 한 개 | 0.5일 |
| D-3 | **부스-역량 매핑 채우기** | ① C존 10개: 역량 1개씩 (이름이 이미 1:1이라 기계적) ② F/L/Y 57개: 역량 3개씩 — **사람이 판단해야 한다**. 구청안대로 가면 F/L/Y는 점수에 관여하지 않으므로 **C존 10개만 채우고 끝낼 수도 있다**(D-1과 함께 결정) | C존만: 0.5일 / 전체: 1.5일 |
| D-4 | **카드 파이프라인 연결** | `ops.jobs` 마이그레이션 + `CardRepository` + `card_worker` 본체 + `/api/cards/*`. 행사 전 **일괄(배치) 생성**이므로 실시간 큐가 과하다면 **관리자 트리거 배치 스크립트**로 먼저 막는 선택지도 있다(훨씬 작다) | 큐: 3~5일 / 배치 스크립트: 1일 |

> D-4의 "배치 스크립트 먼저" 안을 권한다. 행사 전 1회 일괄 생성이 목적이고, 실시간 발급은

## 4. 부하테스트

계획은 [`2026-08-08-행사-부하-용량-점검.md`](2026-08-08-행사-부하-용량-점검.md) §6에 이미 있다. **스크립트가 없을 뿐이다.**

### 목표값 (내부 목표 — 공식 확정 아님)

| 지표 | 목표 |
|---|---|
| 지속 | 100 req/s |
| 스파이크 | 300 req/s |
| LLM 제외 API p95 | < 800ms |
| 오류율 | < 1% |
| 메모리 | 최대치의 70% 이하 |

### 실행 순서

1. **스테이징 분리** — 별도 Supabase 프로젝트 + 마이그레이션 0001~0014 적용.
   **운영 DB에 쏘지 않는다**(가짜 학생이 관리자 목록·집계를 오염시킨다). 0.5일
2. **LLM 차단** — `AI_CHAT_BASE_URL`을 로컬 스텁으로. 1회 완주 $0.01~0.02 × VU = 실제 돈. 0.5일
3. **k6 시나리오 작성** — 학생 1명 전체 여정 1반복:
   가입 → 사진 업로드 → 생성 3회 → 답변 저장 10회 → 완료 → 프로필 → **부스 QR 인증 n회**.
   부스 인증은 8월 계획에 없던 경로다(그 뒤에 들어왔다). 1일
4. **실행·관찰** — 행사용과 **같은 사양**의 Lightsail에서. `docker stats`·`htop` 동시 관찰,
   사진 업로드 동시성에서 메모리가 튀는지가 핵심. 0.5일
5. **결과 기록** — 이 폴더에 `YYYY-MM-DD-부하테스트-결과.md`로 박제
6. **정리** — `POST /api/admin/students/bulk-delete`로 회수

### 부하테스트 전에 끝나 있어야 하는 것

- 웹 서버/카드 워커 분리, `--workers 4` (용량 점검 §7.2-3)
- DB 풀 상향 `min_size=5, max_size=20` + 커넥션 총량 검산 (§7.2-4)
- LLM 호출 타임아웃·재시도·동시성 상한 (§7.2-5)
- Supabase Free → Pro, Lightsail 2GB → 16GB (§7.2-1,2)

→ **인프라 스펙 상향을 먼저 하고 측정한다.** 작은 인스턴스에서 잰 수치는 버리게 된다.

## 6. 결정 대기 (막히면 개발이 멈추는 것)

1. **구청 추천안 수용 여부** — D-1·D-2·D-3 전부가 여기 걸려 있다. **가장 먼저 닫는다.**
2. **F/L/Y 부스를 역량 점수에 넣을지** — 아니면 D-3이 1/6로 줄어든다.
3. **카드 발급을 큐로 할지 배치 스크립트로 할지** — 3~5일 vs 1일.
4. **학생 QR URL에 무엇을 넣을지** — 인쇄 후 변경 불가.
5. **역량 적립 단위** — 코드는 이미 "부스당 +1, 중복 불가". 다르게 갈 이유가 없으면 **현행 확정**으로 닫는다.
