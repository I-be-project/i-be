# 부스 존 구분과 일괄 등록 — 설계 (1단계)

작성 2026-09-11. 부스 명단은 [`../../guides/booths.md`](../../guides/booths.md).

## 배경

행사장 부스 67개(직업체험 57 + 역량체험 10)를 시스템에 올려야 한다. 지금 있는 것은
부스 1건씩 등록하는 관리자 화면, 6자 코드 자동 발급, QR PNG 개별 다운로드,
학생 QR 방문 기록, 부스별 참여 통계다. 동작은 다 하지만 67개 규모를 감당하지 못한다.

- 등록: 관리자 화면에서 67번 입력해야 한다.
- 찾기: 목록이 평평해서 존을 구분할 수 없다.
- 인쇄: QR을 한 장씩 모달로 열어 67번 내려받아야 한다.

## 목표와 비목표

**1단계 목표** — 부스 67개를 존과 함께 등록하고, QR을 한 번에 인쇄하고, 참여 현황을
존별로 본다.

**비목표(2단계)** — 부스별 역량 3개 연결, 페르소나 기반 부스 추천, 학생 역량 수집
진행도. 부스별 역량 매핑 데이터가 아직 없어 1단계에서는 컬럼도 연결 테이블도 만들지
않는다. 근거는 아래 [결정](#결정과-근거) 참고.

## 데이터 모델

`ops.booths`에 `zone` 컬럼 하나를 추가한다. 마이그레이션 `0013_add_booths_zone.sql`.

| 값 | 존 |
|---|---|
| `F` | 직업체험 F(Future)존 |
| `L` | 직업체험 L(Love)존 |
| `Y` | 직업체험 Y(Yourself)존 |
| `C` | 역량체험존 |

- `text not null default ''` + 체크 제약 `zone in ('F','L','Y','C','')`.
  기존 행과 존을 모르는 부스는 빈 문자열로 남는다.
- 존 테이블은 만들지 않는다. 값이 4개로 고정이고 이름도 바뀌지 않는데 테이블을 만들면
  조인만 는다.
- 정렬·필터용 인덱스는 두지 않는다. 전체가 67행이라 순차 조회로 충분하다.

## 이름 규칙

| 존 | `name` | `description` |
|---|---|---|
| F·L·Y | 체험주제 | 기관(업체)명 |
| C | 부스명(안) | 미션 활동 |

학생에게는 기관명보다 무엇을 하는지가 먼저 보여야 한다. 같은 기관이 부스를 여럿
운영하므로(국제메타미디어콘텐츠협동조합 3개, 충남대 생활과학교실 2개) 기관명을 이름으로
쓰면 목록에서 구분되지 않는다.

체험주제 57개는 서로 모두 다르고 가장 긴 것이 34자라 `name`의 100자 제한 안에 든다.
이름이 고유하다는 성질은 시드 스크립트의 중복 판별에도 쓴다.

## 등록 — CSV + 시드 스크립트

`backend/scripts/seed_booths.py`. 기존 `export_students.py`와 같은 방식으로 **관리자 API만
호출한다.** DB에 직접 붙지 않는다.

```
uv run python -m scripts.seed_booths \
    --base-url https://api.cnu-likelion.kr \
    --username admin --password '<비밀번호>' \
    --csv scripts/booths.csv [--dry-run]
```

- 입력 CSV(`backend/scripts/booths.csv`)는 `zone,name,description` 3열. 저장소에 커밋해
  등록 명단의 원본으로 남긴다.
- 실행하면 먼저 `GET /api/admin/booths`로 기존 목록을 받아 **이름이 같은 부스는 건너뛴다.**
  중간에 실패해도 다시 돌리면 안 들어간 것만 들어간다.
- `--dry-run`은 무엇이 새로 등록되고 무엇이 건너뛰어지는지만 출력한다.
- 결과는 stdout 요약(등록 n건, 건너뜀 m건)으로 끝낸다. 코드가 붙은 CSV를 따로 내보내지
  않는다. 인쇄는 아래 인쇄 페이지에서 한다.

DB에 직접 붙지 않는 이유는 코드 발급이다. 6자 코드는 혼동 문자를 뺀 랜덤 값이고 충돌 시
재시도까지 서비스가 처리한다. SQL로 값을 박으면 그 로직을 우회하게 된다.

## QR 일괄 인쇄

`/admin/booths/print` 페이지를 추가한다.

- 존 선택(F·L·Y·C·전체) → 해당 부스의 QR을 격자로 깔고 브라우저 인쇄(`window.print()`)를 쓴다.
- QR 이미지는 이미 있는 `frontend/lib/boothQr.ts`의 `renderBoothQrPng`를 그대로 쓴다.
  새 의존성도 PDF 생성기도 넣지 않는다.
- 한 장에 QR, 체험주제, 기관명, 6자 코드를 함께 찍는다. 카메라가 안 잡힐 때 학생이 코드를
  손으로 입력할 수 있어야 한다.
- 인쇄용 CSS는 `@media print`로 배경·네비게이션을 숨기고 칸이 쪽 경계에서 잘리지 않게 한다.

QR 링크의 base는 서버가 `FRONTEND_ORIGIN`으로 조립해 내려주므로, 로컬 개발 서버에서
인쇄해도 인쇄물에 `localhost`가 박히지 않는다.

## 관리자 목록과 참여 현황

- `BoothListView`에 존 컬럼과 존 필터를 넣는다. 등록·수정 폼에 존 선택을 추가한다.
- 참여 통계 화면은 기존 응답을 그대로 받아 **프론트에서 존으로 묶어 보여준다.** 통계 API는
  바꾸지 않는다. 67행을 화면에서 묶는 데 서버 집계가 필요하지 않다.

## API 변경

| 대상 | 변경 |
|---|---|
| `BoothCreateRequest` | `zone` 추가 (선택, 기본 `''`) |
| `BoothUpdateRequest` | `zone` 추가 (부분 수정) |
| `BoothResponse` | `zone` 추가 |
| `StudentBoothResponse` | 바꾸지 않는다 |

외부 공개 문서(`docs/guides/admin-api.md`)는 부스 API를 다루지 않으므로 영향이 없다.
`docs/guides/architecture.md`의 부스 항목은 함께 갱신한다.

`code`는 그대로 불변이다. 인쇄물에 박히기 때문이다.

## 테스트

- `test_booth_service.py` — 존을 포함한 생성·수정, 존을 안 보낸 기존 요청이 그대로 동작하는지.
- `test_booths_router.py` — 허용되지 않은 존 값이 422로 거부되는지.
- 새 `test_seed_booths_script.py` — 가짜 transport로 CSV 파싱, 중복 건너뛰기, `--dry-run`이
  아무것도 등록하지 않는 것.
- 프론트는 `npm run lint` + `npm run build`. 인쇄 페이지는 표시 전용이라 단위 테스트를 두지 않는다.

## 결정과 근거

**역량 연결 테이블을 지금 만들지 않는다.** 부스별 역량 3개는 주최측 자료에 없는
데이터다. 빈 테이블을 미리 만들어도 2단계에 마이그레이션을 다시 쓰게 되어 비용이 같고,
그 사이 아무도 읽지 않는 테이블이 남는다. 역량 매핑이 정해질 때 한 번에 만든다.

**존을 부스의 컬럼으로 둔다.** 부스는 존 하나에만 속한다. 다대다가 아니므로 연결 테이블이
필요 없다. 역량은 다대다라 2단계에서 연결 테이블이 필요해지는데, 그때도 존은 컬럼으로 남는다.

**시드를 SQL 마이그레이션에 넣지 않는다.** 위 등록 절 참고. 코드 발급 로직을 우회하면
인쇄물과 DB가 어긋날 여지가 생긴다.

## 미해결

- 역량체험 부스 10개의 이름은 주최측 자료에 "부스명(안)"으로 되어 있다. 확정되면 `name`만
  고친다. `code`는 그대로 둔다.
- 부스 명단 자체가 행사 전까지 바뀔 수 있다. 바뀌면 CSV를 고치고 시드를 다시 돌린다.
  이미 등록된 부스의 이름 변경은 스크립트가 하지 않는다. 관리자 화면에서 고친다.
